# 视频学习总结

## 目标

把用户提供的本地视频目录整理成便于复习的中文笔记：每个视频一份 Markdown，总目录一份索引。优先在本机处理，不上传视频；不修改、移动或删除原视频。

## 输入与输出

- 使用用户本次指定的目录；不要擅自改用其他下载目录。若路径不存在或不明确，先检查路径拼写及盘符，再只在仍无法确定时询问。
- 递归查找常见视频格式（如 MP4、MKV、MOV、AVI、WebM、M4V、WMV、TS），按文件名自然排序。跳过输出目录和非视频文件，避免把已生成的笔记当作输入。
- 用户指定输出位置时，使用指定位置。默认在章节目录内创建或复用总结文件夹，名称由章节目录的完整原名直接加上 `视频总结` 组成。例如，`第四章：沟通基础(下)` 对应的子文件夹名为 `第四章：沟通基础(下)视频总结`。
- 将 `00-视频总结索引.md` 和按顺序编号的单视频总结（如 `01-主题名称.md`）一并写入该输出目录。文件名需安全、简洁，并保留可辨识的原标题。

## 阅读流程

1. 盘点视频并读取时长等可用元数据；查找已有字幕。优先利用字幕和完整音轨，不要只凭文件名推断内容。
2. 需要语音识别时，先检查本机已有的 FFmpeg、转录工具、模型和运行环境。优先完整转录音轨；可用 GPU 时优先使用 GPU，并以转录工具的运行时状态或日志确认加速确实生效。仅检测到 NVIDIA 显卡不足以证明转录用了 GPU。
3. 缺少必要依赖时，按用户已表达的下载授权，只安装完成任务所需的最小工具或模型；优先使用隔离的项目/虚拟环境，避免不必要的系统级更改。下载或安装不可行时使用现有能力继续，并说明限制。GPU 不可用时回退 CPU，不要因此中断可完成的任务。
4. 对课件、白板、图表、章节标题或识别不清的专有名词，按场景/页面变化抽取代表帧并核对画面；必要时结合 OCR。抽帧用于交叉核实，不要声称逐帧人工观看。
5. 将转录、字幕和画面证据相互核对。纠正明显的语音识别错误；对无法确认的人名、数字、术语或因果关系，删去过度确定的表述或明确标为听辨不确定。不要补入视频未支持的事实。
6. 逐个完成所有目标视频，检查摘要数量、索引链接、视频时长和输出文件；如个别视频损坏、无声或无法识别，保留其他结果，并在索引中清楚标记该视频的限制。

## 摘要格式

每个视频的 Markdown 尽量采用以下结构，并按内容调整章节，不为凑标题重复信息：

```markdown
# 视频标题

- **时长：**约 … 分钟
- **形式：**讲授、访谈、案例讨论等（能确认时填写）

## 内容总结

### 1. 主题
用连贯文字概括观点、论据、案例及它们之间的关系。

## 可执行提醒
- 从视频内容中提炼可落实的做法；没有明确做法时可省略此节。

## 一句话
用一句话概括本视频的核心。
```

- 以概念和逻辑关系组织笔记，不逐句照抄转录稿。保留关键案例、数字、框架和结论，同时区分讲师观点、学员经历与总结者归纳。
- 关键结论或案例在时间戳可靠且有助于回看时，可附大致时间戳；不要伪造精确时间。
- 索引列出序号、视频标题、时长和对应摘要链接；有多条视频时补一段整组课程的主线速览。记录必要的听写不确定性或处理限制。
- 最终回复用中文给出输出目录、完成数量，以及任何未能完整处理的视频；不要只报告转录文件而遗漏可读摘要。
