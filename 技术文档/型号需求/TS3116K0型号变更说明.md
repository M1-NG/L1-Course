## 1. 已确认的需求

- TS3116K0 暂时使用功能码 `27`，即 `FUNC_TYPE_MODELCHANGE`。
- 有效授权码 `27` 的设备，显示型号改为市品 `TS2116K0`。
- 无型号变更授权的设备，继续显示 `TS3116K0`。
- 旧固件升级到包含本次修改的固件并重启后，读取已有授权码，执行相同转换。
- 用户补充要求：在 `V4.6.1.8_10` 型号变更授权成功后，必须拒绝安装不支持该型号转换的旧固件，避免降级后显示型号变回 TS3116K0。
- 冷省先不处理。本次目标为村品改市品，县品、欧品的新增转换后续处理。

旧固件可升级到包含本次修改的固件；有效型号变更授权存在时，不支持该转换的旧固件必须在刷写前被拒绝。本方案同时包含显示转换与升级兼容保护，不通过降级清除授权或恢复原显示型号。

本次将型号第三个字符从 `3` 改为 `2`。C/C++ 字符串下标从 0 开始，因此对应 `display_model[2]`。

```text

```

产品型号与软件版本号是独立字段。软件版本号在 `MPU_PUB_API.cpp` 第 1754 行的 `MPU_PUB_GetDeviceVersion()` 中读取，第 1806 行生成 `V4.x.x.x-Build...`。本次无需为了型号转换修改软件版本数字。

品类矩阵中的“村品、市品迭代后，寄生品必须迭代”作为后续县品、欧品迭代的验收依据，具体能力差异和正式授权码需另行确定。

### 3.1 修改前

```cpp
    else if (func_codes[FUNC_TYPE_MARKET_MODELCHANGE]
```

### 3.2 修改后

将上述分支完整替换为：

```cpp
    else if ((func_codes[FUNC_TYPE_MODELCHANGE]
              && strcasecmp(raw_model, "TS3116K0") == 0)
             || (func_codes[FUNC_TYPE_MARKET_MODELCHANGE]
                 && strncmp(raw_model, "TS3", 3) == 0))
```

两个条件分别表示：

1. 新增规则：有效授权中存在码 27，且原始型号为 TS3116K0，转换为 TS2116K0。`strcasecmp()` 允许原始配置大小写不同。
2. 已有规则：存在码 33，且原始型号以 TS3 开头，继续执行已有市品转换。

第 348 行原有的 TS8 分支保留：码 27 对原始 TS8 型号仍执行既有 TS8 到 TS7 的转换。

### 3.4 授权后禁止不兼容降级

用户提供的复现：`V4.6.1.8_10` 授权后显示 TS2116K0，仍可安装不支持型号变更的旧固件，随后显示 TS3116K0。期望是在更新校验阶段拒绝这种旧包，保持当前固件、授权和型号。

当前源码存在两处相关检查：

| 位置 | 当前条件 | 问题/处理要求 |
| --- | --- | --- |
| CBaseUpdate.cpp 第 72、883 行 | 码 33，最低目标版本 4.6.1.8，数值四段比较 | 当前已有保护；临时码 27 不能遗漏，且需验证实机包含该代码 |

升级检查设计：

1. 保留原有码 33 保护；将“码 27 且升级身份为 TS3116K0”纳入相同市品兼容检查，其他型号的码 27 规则不自动套用。
2. 使用 `MPU_PUB_HasFuncCode()` 读取有效授权，不能只按显示型号缓存判断。授权刚保存但尚未重启时也要拒绝不兼容包。
3. 读取包内真实目标版本，使用已有 `CompareDottedVersion()` 进行四段数值比较；强制保护在 EnableCheck 提前返回之前执行。
4. 不兼容目标返回 `IDVR_SYS_UPDATE_ERROR_VERSION` 并走错误出口，不能返回普通降级确认 `IDVR_SYS_UPDATE_PREVIOUS_VERSION`。
5. 避免旧 4.6.1.3 的 strcmp 条件继续误判已走新保护的 TS3116K0，保留其他型号既有语义。
6. 本地预检、复制后复检、远程校验均验证拒绝结果，不执行后续刷写，不清授权或改型号。

当前 4.6.1.8 门槛是源码候选边界。截图没有说明 `_10` 含义，也没提供旧包版本与实际功能码。如果同为 4.6.1.8 的部分构建仍不支持转换，必须按发布记录增加可验证的构建/能力区分，单纯四段比较不能满足该情况。

### 4.1 生效时机

型号有缓存：`MPU_PUB_API.cpp` 第 600 行使用 `if (!s_bInit)` 控制首次读取；设备描述第 152 行还使用 `s_bGetDevCap_pub` 缓存。

因此，本方案按“授权后重启设备生效”验收。旧固件升级并重启后，新进程会重新读取配置和授权码。仅重新打开系统信息页不能保证刷新型号缓存。

如果后续要求授权后立即刷新，需要另行设计型号缓存失效机制，并覆盖设备描述、本地界面和远程接口；单独修改本分支不能实现即时刷新。
