# 项目模块地图与需求定位

本文按仓库当前目录和构建入口整理，目的是让开发者能从需求快速找到代码、配置和打包位置。项目是以 C/C++ 为主的嵌入式 Linux NVR 固件；`code/` 是主要源码区，`edvr` 是设备端主程序。

相关文档：[项目阅读指南](项目阅读指南.md)、[构建脚本与 Shell 学习整理](../构建与发布/构建脚本与Shell学习整理.md)、[TS3116K0 本周任务分析](../型号需求/TS3116K0本周任务分析.md)。

## 仓库顶层

| 路径 | 职责 | 常见改动 |
| --- | --- | --- |
| `code/` | 主程序、中间件、芯片 SDK、文件系统和资源 | 功能代码、驱动适配、启动内容、界面资源 |
| `menuconfig/` | 各产品配置及 `Kconfig` | 芯片、通道规格、功能开关 |
| `model/` | 型号配置、版本配置和版本脚本 | 型号标识、版本号、发布基线 |
| `customized/` | 客户或品牌定制构建、资源和配置 | 客户定制型号、Logo、界面差异 |
| `tools/` | 固件升级、生产测试、烧录及桌面辅助工具 | 升级/生产流程配套工具 |
| `build-*.sh` | 按型号选择配置、编译并调用打包 | 全量构建入口 |
| `makefs-*.sh` | 整理目标文件系统、生成升级或烧录产物 | 固件打包、分区内容 |
| `partition_merge.sh`、`usbupgrade.sh` 等 | 镜像合并和升级包辅助脚本 | 发布流程中的单项处理 |

## `code/` 模块

### 应用层：`code/app/`

| 目录 | 职责与入口 |
| --- | --- |
| `GUI_8x/` | 本地 NVR 图形界面并链接生成 `edvr`。从 `gui_main.c` 的 `__wrap_main()`、`EGUIMain()` 开始，再按文件名前缀找页面。 |
| `upgrading/`、`upgrading-ms621/`、`upgrading-3798m/` | 不同芯片平台使用的升级界面/程序，具体选择由 `code/common.mak` 的平台分支决定。 |
| `defaultip/` | 默认网络参数相关小程序。 |
| `md5file/`、`md5firmware/` | 文件或固件校验工具。 |
| `console/`、`newchek/`、`updatelogo-3798m/` | 独立辅助程序；确认用途时从各自 `Makefile` 和 `main()` 入口追踪。 |

### 业务与平台层：`code/midware/`

| 路径 | 职责 | 从哪里开始 |
| --- | --- | --- |
| `DVR_SDK/` | NVR 业务库，按子目录编译为平台 `.so`；公共设备能力接口集中在 `MPU/`。 | `DVR_SDK/build`、`MPU/`、以及对应业务模块的 `Makefile` |
| `DVR_SDK/SYS/` | 系统级业务和升级/版本处理代码。 | `CBaseUpdate.cpp`、同目录头文件 |
| `DVR_SDK/AVL/`、`AVP/`、`STR/`、`BAK/` | 常见录像、回放、存储、备份相关业务模块。 | 先查 GUI/MPU 调用，再跟进对应 API 实现 |
| `DVR_SDK/USR/`、`LOG/`、`PTZ/`、`Insight/`、`SnapShot/` | 用户、日志、云台、智能分析、抓图等业务模块。 | 按目录名定位，再从调用处核对具体边界 |
| `SysSDK/` | 芯片与系统能力适配，包含 `mi/`、`mpp/`、`msp/` 等平台实现。 | `SysSDK/build`、`include/` 和当前平台实现目录 |
| `EGUI/` | Embedded GUI 框架：窗口、消息、控件、绘图和输入。 | `src/main/main.c`，再看 `src/kernel/`、`src/gui/` |
| `netsdk/` | 网络客户端和服务端组件，包含 ONVIF、RTSP、TPS、P2P、TRTC 等子工程。 | `netsdk/Makefile` 及 `OnvifClient2.0/`、`TP2P/`、`TPS/` 等目录 |
| `lib28181/` | GB28181 服务。是否编译受型号配置开关控制。 | `menuconfig/*.config` 中 `CONFIG_ENABLE_GB28181_SERVICE`、`lib28181/` |
| `ipcuc/` | IPC 搜索、登录以及网络摄像机接入相关公共组件。 | `ipcuc/` 下对应子目录和 GUI 的 IPC 调用 |
| `history_rtsp_pull/` | 可选的历史 RTSP 拉流/回放支持。 | 对应型号的 `CONFIG_ENABLE_HISTORY_RTSP_PULL` 和 `include/`、`src/` |
| `tps_protocol/`、`tps_encrypt/` | TPS 协议定义/实现及加密接口。 | 协议头文件、实现目录和 `EncInterface.h` |
| `base/`、`sn/`、`signalhandle/`、`zram/` | 公共基础库、设备序列号相关库、信号处理、压缩交换等支持模块。 | 各自 `Makefile` 和被调用的接口 |
| `modules/` | SQLite、curl、wolfSSL、zlib、磁盘/USB 等第三方或通用依赖。 | 先确认需求确实属于依赖库，再检查该库构建脚本 |

`DVR_SDK` 的模块边界以实际接口调用为准：从界面/API 的调用点进入，再查相应 `.cpp`、头文件和模块 `Makefile`，不要只按目录名推断完整行为。

### 芯片、库、文件系统和资源

| 路径 | 职责 | 阅读提示 |
| --- | --- | --- |
| `code/chipsdk/` | 芯片厂商提供的头文件、驱动接口和 SDK 库。 | 平台底层依赖；先确认适配层无法满足需求，再考虑改动。 |
| `code/libs/` | 按平台保存的预编译运行库、工具和升级依赖。 | 平台与库目录的对应关系见 `code/common.mak`。 |
| `code/newfs/` | rootfs 目录树、型号覆盖文件、init 脚本及文件系统镜像构建脚本。 | 启动问题优先看 `fs1_<芯片>/etc/init.d/` 和 `buildfs_<芯片>.sh`。 |
| `code/res/` | 字体、语言、图片和界面资源。 | 界面字符串还需查看 `GUI_8x/language.c`、`gui_restext.h`。 |

## 主要依赖与构建路径

```mermaid
flowchart LR
    MODEL[型号 build-*.sh] --> CONFIG[menuconfig 型号配置]
    CONFIG --> MAKE[code/Makefile 与 common.mak]
    MAKE --> SDK[SysSDK 与厂商 chipsdk]
    MAKE --> BIZ[DVR_SDK 业务库]
    MAKE --> NET[netsdk 与 lib28181]
    MAKE --> UI[EGUI 与 GUI_8x]
    BIZ --> EDVR[edvr]
    NET --> EDVR
    SDK --> EDVR
    UI --> EDVR
    EDVR --> PACK[makefs-*.sh]
    FS[code/newfs 文件系统内容] --> PACK
    RES[code/res 资源] --> PACK
    PACK --> IMAGE[固件与升级包]
```

这张图表示主要输入和产物关系。实际编译目标顺序、条件编译和隐式依赖以 [code/Makefile](../../code/Makefile)、[code/common.mak](../../code/common.mak) 及当前型号 `.config` 为准。构建脚本将 `menuconfig/<型号>.config` 复制为 `code/.config`，不要把生成文件当作型号配置源。

设备启动可从 `code/newfs/fs1_<芯片>/etc/init.d/rcS` 追踪到挂载脚本和 `rootapp`，再跟到 `/usr/lib/edvr`。TS3116K0 的具体启动链和 GUI 消息流程见[型号任务分析](../型号需求/TS3116K0本周任务分析.md)。

## 按需求找代码

| 需求类型 | 优先入口 | 同时核对 |
| --- | --- | --- |
| 新增/修改本地 GUI 页面、按钮、文字 | `code/app/GUI_8x/gui_*.c` | `gui_main.c`、`language.c`、`gui_restext.h`、`code/res/` |
| 预览、录像、回放、备份 | `GUI_8x` 对应 `gui_preview*`、`gui_playback*`、`gui_backup*` | `DVR_SDK/MPU/` 对外 API 及 `AVL/AVP/STR/BAK/` 实现 |
| IPC 添加、登录、配置或流接入 | `GUI_8x/gui_source_device_manage.c`、`ipcuc/` | `netsdk/` 中 ONVIF、RTSP、TPS/P2P 组件及对应 API |
| GB28181、ONVIF、RTSP、P2P、TRTC | `code/midware/lib28181/` 或 `netsdk/` 对应子目录 | 型号 `.config`、`Kconfig`、`common.mak` 的编译宏和链接项 |
| 录像机业务 API、设备能力或型号能力 | `DVR_SDK/MPU/` | 调用该 API 的 GUI/网络入口、授权和型号配置 |
| 升级、版本比较、跨型号升级 | `DVR_SDK/SYS/CBaseUpdate.cpp`、`DVR_SDK/MPU/` | `netsdk/TPS/`、`tps_encrypt/`、`model/`、根目录 `makefs-*.sh` |
| 芯片编解码、显示、音频、GPIO 或板级行为 | `SysSDK/` 当前平台目录 | `chipsdk/`、`libs/`、`common.mak` 中芯片分支 |
| 功能开关、通道数、工具链、目标芯片 | `menuconfig/Kconfig` 和型号 `.config` | `code/common.mak` 的配置到编译宏映射 |
| 启动、挂载、服务、rootfs 文件 | `code/newfs/fs1_<芯片>/` | `code/newfs/buildfs_<芯片>.sh` 和根目录 `makefs-*.sh` |
| 字体、语言、Logo 或屏幕资源 | `code/res/`、`code/app/GUI_8x/` | 打包脚本实际复制的资源路径 |
| 生产测试、烧录或 PC 辅助流程 | `tools/` | 根目录打包脚本和型号配置 |
| 崩溃、信号或 core 文件 | `code/midware/signalhandle/` | 仓库根目录的 [stack_debug.md](../../stack_debug.md) 和对应未剥离符号 |

## 建议的阅读与实现顺序

1. 明确目标型号、复现步骤、预期行为和验收方式。
2. 用下表从需求定位首个 GUI、API、系统或资源入口；用 `rg -n "关键词" code menuconfig model` 找调用关系。
3. 顺着接口调用查到负责实现的模块，并检查是否被型号配置、授权、芯片分支或运行时开关限制。
4. 若涉及功能开关，核对 `menuconfig/Kconfig`、型号 `.config` 和 `code/common.mak`，确认配置最终映射到编译宏/链接库。
5. 若涉及固件内容，沿 `build-*.sh` → `code/Makefile` → `makefs-*.sh` → `code/newfs/buildfs_*.sh` 确认产物路径。
6. 修改前后查看 `git status` 和 diff；本仓库没有通用单元测试套件，验证通常需要目标平台构建及对应设备功能验收。

第一次读代码建议依次看：[项目阅读指南](项目阅读指南.md)、`code/Makefile`、目标型号配置、`GUI_8x/gui_main.c`、对应业务 API 和实现模块。做 TS3116K0 型号需求时，再阅读[本周任务分析](../型号需求/TS3116K0本周任务分析.md)与[型号变更说明](../型号需求/TS3116K0型号变更说明.md)。
