# nvr4.6 项目阅读指南

这份文档是给第一次接触本项目的人看的，只负责说明“项目是什么、先看哪里、各目录做什么、怎么理解启动和构建流程”。

当前代码基线：

- Git 分支：`develop`
- 最近提交：`aa310920dea42d3c051f3ca367dbd80ab5df30c2`（2026-10-09）
- 项目类型：嵌入式 Linux NVR 固件
- 主要语言：C / C++ / Shell / Makefile
- 主程序：`edvr`

## 1. 先建立整体认识

这个项目不是 Windows 桌面程序，也不能直接双击运行。它会在 Linux 环境中使用指定的交叉编译工具链，编译设备端程序和依赖库，最后打包成可烧录或升级的 NVR 固件。

可以先用一句话理解编译结果：

```text
源码和第三方库
    -> 各模块静态库/动态库
    -> 主程序 edvr
    -> rootfs、app 等文件系统内容
    -> NVR 固件或升级包
```

## 2. 根目录怎么认

| 路径 | 作用 | 新手建议 |
| --- | --- | --- |
| `code/` | 项目主要代码 | 最常看，下面的指南重点介绍 |
| `menuconfig/` | 各型号编译配置 | 修改型号能力时先看 |
| `model/` | 型号、版本号、发布参数 | 发版本时看，平时不要随意改 |
| `customized/` | 联想、康佳等定制版本 | 做定制型号时看 |
| `tools/` | 升级、烧录、测试和 Windows 辅助工具 | 与主程序阅读分开 |
| `build-*.sh` | 各型号完整构建入口 | 编译时从这里开始 |
| `makefs-*.sh` | 生成文件系统和打包固件 | 通常由构建脚本调用 |
| `partition_merge.sh` | 分区合并相关处理 | 打包流程使用 |
| `changedevtype.sh` | 切换设备类型 | 使用前先确认型号 |
| `readme (版本发布说明).txt` | 项目旧的发布流程说明 | 有历史参考价值，命令可能已过时 |
| [崩溃地址定位](../../stack_debug.md) | NVR 崩溃地址分析说明 | 排查崩溃时直接看 |

| `code/midware/EGUI/` | Embedded GUI 框架 |
| `code/midware/netsdk/` | 网络客户端、协议和网络能力 |
| `code/midware/lib28181/` | GB28181 相关实现 |
| `code/midware/modules/` | 大量第三方或小型基础模块 |
| `code/chipsdk/` | 芯片厂商提供的头文件和库 |

- `chipsdk/`、`modules/` 中很多内容是第三方或厂商代码，第一次阅读时先当成“黑盒依赖”，不要从这些目录开始。
- `code/.config` 是构建脚本从 `menuconfig/` 复制出来的当前型号配置。不要把它当成所有型号共用的配置源。

## 4. GUI 应该从哪里开始

建议按下面的顺序看：

1. `code/midware/EGUI/src/main/main.c`

   负责进入 EGUI 框架。调用关系可以理解为：

   ```text
   my_ecos_main()
       -> InitEGUI()
       -> EGUIMain()
       -> TerminateEGUI()
   ```

2. `code/app/GUI_8x/gui_main.c`

   这是本地界面最核心的文件。

   - 约第 8142 行：`__wrap_main()`，负责接入主程序入口。
   - 约第 9305 行：`EGUIMain()`，负责初始化界面并进入主流程。

   `EGUIMain()` 中可以先找这些步骤：

   ```text
   handle_signal_init()       初始化信号处理
   InitGui()                  初始化 GUI
   MPU_PUB_GetDeviceCap()     读取设备能力
   SetDvrLanguage()           设置语言
   CreateGuiDesktop()         创建桌面
   CreateStartWnd()           创建启动画面
   ```

3. `code/app/GUI_8x/Makefile`

   这个 Makefile 会把 `GUI_8x` 下的 `.c` 文件编译为目标文件，最终生成：

   ```text
   RELEASE/edvr
   DEBUG/edvr_debug
   ```

4. 按功能继续查看：

| 文件或文件名前缀 | 主要功能 |
| --- | --- |
| `gui_main.c` | 主入口、主窗口、整体流程 |
| `gui_common.c/.h` | 公共控件和公共函数 |
| `gui_preview*.c` | 预览画面 |
| `gui_playback*.c` | 本地回放 |
| `gui_remote_playback*.c` | 远程回放 |
| `gui_config_*.c` | 各类设备配置页面 |
| `gui_insight_*.c` | 智能分析、人形、车辆、人脸等界面 |
| `gui_ptzcontrol*.c` | 云台控制 |
| `gui_backup*.c` | 备份功能 |
| `gui_source_device_manage.c` | IPC 源设备管理 |
| `gui_restext.h`、`language.c` | 界面文字和语言资源 |

`GUI_8x` 目录很大，不要从第一个文件顺着读到最后一个。先抓住“主流程”，再按实际功能找到对应的 `gui_*` 文件。

## 5. 构建流程怎么理解

所有完整构建脚本都在项目根目录，每个脚本对应一个型号。

| 构建脚本 | 配置文件 | 打包脚本 |
| --- | --- | --- |
| `build-ts3116k0.sh` | `menuconfig/TS3116K0.config` | `makefs-631g.sh` |
| `build-ts81xxd3x.sh` | `menuconfig/TS81XXD3X.config` | `makefs-621q.sh` |
| `build-ts8232c.sh` | `menuconfig/TS8232C6.config` | `makefs-3536c.sh` |
| `build-ts8232c10.sh` | `menuconfig/TS8232C10.config` | `makefs-931g.sh` |
| `build-ts8836m.sh` | `menuconfig/TS8X36M.config` | `makefs-3796m.sh` |
| `build-ts8xxxg.sh` | `menuconfig/TS8XXXG.config` | `makefs-931g.sh` |

典型流程如下：

```text
./build-型号.sh
    -> 复制 menuconfig/型号.config 到 code/.config
    -> make -C code
        -> 编译中间件、SDK、网络库、EGUI、GUI
    -> ./makefs-型号.sh
        -> 组织文件系统
        -> 生成固件或升级包
```

编译脚本通常接收三个位置参数，实际运行时必须以项目当前约定为准：

```sh
./build-型号.sh 版本号 参数1 参数2
```

重要提醒：

- 编译应在 Linux 或 WSL 中进行，并安装与型号匹配的交叉编译工具链。
- Windows PowerShell 通常不能直接完成本项目构建。
- 编译日志主要看项目根目录的 `build.txt`。
- 根目录旧发布说明里出现的是 SVN 和旧脚本名，当前仓库实际使用 Git；不要把旧文档中的命令直接照搬。

## 6. 各型号配置怎么看

关键配置在 `menuconfig/*.config` 中，常用字段包括：

| 字段 | 含义 |
| --- | --- |
| `CONFIG_CHIP_TYPE` | 芯片平台 |
| `CONFIG_TOOLCHAIN` | 交叉编译工具链前缀 |
| `CONFIG_CHANS` | 型号通道规格 |
| `CONFIG_MAX_CHANNEL` | 最大通道数 |
| `CONFIG_ENABLE_VRS` | 是否启用 VRS 相关能力 |

当前配置对应关系：

| 配置 | 芯片类型 | 通道规格 | 最大通道 |
| --- | --- | --- | --- |
| `TS3116K0.config` | `sstar631g` | `mini16` | 16 |
| `TS81XXD3X.config` | `mstar621q` | `mini16` | 16 |
| `TS8232C6.config` | `hisi3536c` | `mini32` | 36 |
| `TS8232C10.config` | `sstar931g` | `mini32` | 36 |
| `TS8X36M.config` | `hisi3796m` | `mini36` | 36 |
| `TS8XXXG.config` | `sstar931g` | `mini64` | 64 |

## 7. 想改功能时先找哪里

| 需求 | 优先查看 |
| --- | --- |
| 改本地界面文字、控件、页面 | `code/app/GUI_8x/`、`code/res/` |
| 改预览、回放、备份逻辑 | `gui_preview*`、`gui_playback*`、`gui_backup*` |
| 改设备配置页面 | `gui_config_*` |
| 改智能分析功能 | `gui_insight_*` |

| 改设备核心业务接口 | `code/midware/DVR_SDK/` |
| 改芯片适配 | `code/midware/SysSDK/`、`code/chipsdk/` |

## 8. 新手阅读和修改规则

1. 不要一开始浏览整个仓库。先看 `code/Makefile`，再看 GUI 启动链，最后按具体功能查看模块。
2. 不要修改厂商目录中的头文件和预编译库，除非已经确认必须同步替换。
3. 不要直接改 `code/.config`。要改型号配置，应从 `menuconfig/` 对应文件入手。
4. 不要手工修改编译产物、`RELEASE`、`DEBUG`、临时目录或已打包固件。
5. 改代码前先执行 `git status`。当前工作区已经存在不少修改，不能使用会丢弃文件的操作。
6. 部分旧源码注释可能是 GBK/ANSI 编码。编辑器显示乱码时先切换编码查看，不要直接批量转码，以免产生大量无意义差异。
7. 遇到崩溃地址时看仓库根目录的 [stack_debug.md](../../stack_debug.md)，不要只拿 `si_addr` 去执行 `addr2line`。
8. 第一次编译前先确认当前型号、工具链、目标 Linux/WSL 环境，再运行对应 `build-型号.sh`。

## 9. 推荐的第一次阅读清单

按这个顺序看，最容易建立完整认识：

1. `code/Makefile`
2. 对应型号的 `menuconfig/*.config`
3. 对应型号的根目录 `build-*.sh`
4. `code/app/GUI_8x/Makefile`
5. `code/midware/EGUI/src/main/main.c`
6. `code/app/GUI_8x/gui_main.c`
7. 根据具体任务，再看 `gui_preview*`、`gui_playback*` 或某个 `gui_config_*` 文件
8. 排查崩溃时看仓库根目录的 [stack_debug.md](../../stack_debug.md)
