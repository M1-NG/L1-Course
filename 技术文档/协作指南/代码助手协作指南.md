# 代码助手协作指南

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 项目概述

嵌入式 Linux NVR（网络录像机）固件。C/C++，交叉编译，主程序为 `edvr`。产出链路：

```
chipsdk(厂商库) -> SysSDK(芯片适配) -> DVR_SDK(业务库 .so) -> netsdk/lib28181 -> EGUI(界面框架) -> GUI_8x -> edvr
                                                                                                      -> newfs/rootfs -> 固件/升级包
```

人工阅读指南见[项目阅读指南](../项目导读/项目阅读指南.md)（目录导航、GUI 阅读顺序、型号对照表）；崩溃定位方法见仓库根目录的 [stack_debug.md](../../stack_debug.md)。本文件只补充日常操作所需内容。

## 构建

**必须在 Linux 或 WSL 下构建**，并安装对应芯片的交叉编译工具链。Windows 原生环境无法完成构建。所有工具链前缀在 [code/common.mak](../../code/common.mak) 中按 `CONFIG_CHIP_TYPE` 分支定义。

完整构建（每个型号一个入口脚本，在仓库根目录执行）：

```sh
./build-型号.sh <版本号> <参数2> [upg]
# 例：./build-ts8232c.sh 4.5.4.3 all upg
```

脚本做三件事：把 `menuconfig/型号.config` 复制为 `code/.config` → `make -C code clean; make -C code` → 调用 `./makefs-型号.sh` 打包。第三个位置参数为 `upg` 时会额外打一次升级包。日志输出到根目录 `build.txt`（脚本会自动 grep `error:` 并打印成功/失败横幅）。

| 构建脚本 | 配置文件 | 打包脚本 | 芯片 |
| --- | --- | --- | --- |
| `build-ts3116k0.sh` | `menuconfig/TS3116K0.config` | `makefs-631g.sh` | sstar631g |
| `build-ts81xxd3x.sh` | `menuconfig/TS81XXD3X.config` | `makefs-621q.sh` | mstar621q |
| `build-ts8232c.sh` | `menuconfig/TS8232C6.config` | `makefs-3536c.sh` | hisi3536c |
| `build-ts8232c10.sh` | `menuconfig/TS8232C10.config` | `makefs-931g.sh` | sstar931g |
| `build-ts8836m.sh` | `menuconfig/TS8X36M.config` | `makefs-3796m.sh` | hisi3796m |
| `build-ts8xxxg.sh` | `menuconfig/TS8XXXG.config` | `makefs-931g.sh` | sstar931g |

增量/局部构建（`code/Makefile` 的伪目标，依赖 `code/.config` 已存在）：

```sh
make -C code guiapp        # 只重编 GUI 主程序（隐式依赖 libipc）
make -C code egui          # 只重编 EGUI 框架
make -C code dvrsdk        # 只重编 DVR_SDK 业务库
make -C code netsdk        # 只重编网络库
make -C code syssdk        # 只重编芯片适配层
make -C code lib28181      # GB28181（受 CONFIG_ENABLE_GB28181_SERVICE 控制）
make -C code up            # 只重编升级程序
make -C code clean         # 全部清理；每个模块另有 xxx_clean 目标
make -C code/app/GUI_8x    # 直接在 GUI_8x 目录编译
```

**没有单元测试框架**。验证方式是编译通过 + 在设备上跑预览/回放/升级等实际功能。`-DAUTOTEST_OUT -DPYTHON_AUTOTEST_OUT` 只是 GUI 自测输出开关，`tools/product_test_tool` 是独立生产测试工具，都不是可运行的测试套件。

## 配置系统

`menuconfig/*.config` 是各型号配置源；`code/.config` 是构建脚本复制出的**当前型号**配置，已被 gitignore。**不要直接改 `code/.config`**，改能力开关应改 `menuconfig/` 下对应文件（`Kconfig`/`mconf` 提供 menuconfig 界面）。

[code/common.mak](../../code/common.mak) 是配置到编译变量的唯一映射点：它把 `CONFIG_CHIP_TYPE/CHANS/MAX_CHANNEL/TOOLCHAIN` 转成 `CHIP_TYPE/CROSS_COMPILE/CHANS` 等，并把每个 `CONFIG_*` 开关转成对应的 `-D...` 宏（如 `CONFIG_ENABLE_GB28181_SERVICE=y` → `-DGB28181_SERVICE`）和链接参数。新增型号能力开关时，需要同时在 `common.mak` 加映射、在 `menuconfig/*.config` 加字段。

型号差异集中在 `common.mak` 的 `ifeq ($(CHIP_TYPE),...)` 分支：工具链路径、`SDK_CFLAGS`、`SDK_LIB_PATH`、`SDK_GUI_LDFLAGS`、`CHANS` 相关宏。

## 代码结构

- [code/app/GUI_8x/](../../code/app/GUI_8x/) —— 本地 GUI 主程序，约 190 个 `.c` 平铺在同一目录，全部编进 `edvr`。入口：`__wrap_main()`（[gui_main.c:8142](../../code/app/GUI_8x/gui_main.c#L8142)，靠链接期 `-Wl,--wrap,main` 接管）→ `EGUIMain()`（[gui_main.c:9305](../../code/app/GUI_8x/gui_main.c#L9305)）。按文件名前缀定位功能：`gui_preview*` 预览、`gui_playback*` 回放、`gui_config_*` 配置页、`gui_insight_*` 智能分析、`gui_backup*` 备份。VRS 平台独有文件由 `Makefile` 里的 `CONFIG_ENABLE_VRS` 条件控制，不要在其它平台引用。
- `code/midware/DVR_SDK/` —— NVR 核心业务库，每个子目录编译为一个 `.so`（目录名即模块名，见 `DVR_SDK/build`：`TARGET=lib$dir.so`），产物放 `lib_$(CHIP_TYPE)/`。`MPU` 是设备能力/配置接口，`PUB` 是公共接口。
- `code/midware/SysSDK/` —— 芯片能力和系统封装，各芯片实现不同。
- `code/midware/EGUI/` —— Embedded GUI 框架，入口 `src/main/main.c`；需先跑 `CrossConfigure.sh $(CHIP_TYPE) $(CHANS)` 生成 Makefile（该 Makefile 被 gitignore）。
- `code/midware/netsdk/`、`code/midware/lib28181/` —— 网络协议与服务。
- `code/chipsdk/`、`code/midware/modules/` —— 厂商 SDK 与第三方库，**当作黑盒依赖，不要修改**。
- `code/newfs/` —— rootfs 内容与启动/挂载脚本，`buildfs_<芯片>.sh` 生成文件系统镜像。
- `code/libs/<soc>/` —— 各平台的预编译库（`v500`=hisi3536c、`v320`=hisi3796m、`ms621`、`sstar631`、`sstar931`），由 `common.mak` 的 `UPLIBPATH` 选择。

## 版本与定制

- 版本号在 `model/*Version.ini` 与 `model/version.*`；批量改版本用 `./model/Changeversion.sh 4.x.y.z`。`model/*Model.cfg` 定义型号信息。发布时不要在编译目录手工改动产物。
- 客户定制版见 `customized/`（`model-lenovo`、`model-konka` 等），编译脚本为 `customized/build-*-3536c.sh`；联想定制会覆盖 EGUI 的 Makefile 生成脚本以追加 `-DLENOVO_VERSION`。
- 跨型号升级包由 `changedevtype.sh <源型号> <目标型号>` 制作（依赖 `tmp/` 下已有的源型号升级包）。

## 打包产物

`makefs-*.sh` 在根目录生成临时目录：`rootfs/`、`update/`、`release/`，最终产物复制到 `tmp/<大写的型号>/`（`upg` 再产出一份到 `tmp/Upgrade/<型号>/`）。`tmp/`、`rootfs/` 已被 gitignore。调试符号包 `edvr.bin`（gzip tar，含未 strip 的 `edvr`、各 `.so`、`edvr.map`、`manifest.txt`）只放在版本输出目录，不进固件。

## 注意事项

1. 编译产物 `RELEASE/`、`DEBUG/`、`edvr`、`*.o`、`*.a`、`*.so` 以及已打包固件都不要手工修改，改动只落在源码。
2. 部分旧源码注释是 GBK/ANSI 编码，编辑器显示乱码时切编码查看，**不要批量转码**，会产生大量无意义 diff。
3. 厂商头文件与预编译库（`chipsdk/`、`modules/`、`libs/`）除非确认必须同步替换，否则不改。
4. 根目录 `readme (版本发布说明).txt` 是历史文档，描述的是 SVN 工作流和旧脚本名；当前仓库使用 Git，命令不要照搬。
5. 排查崩溃时按仓库根目录 [stack_debug.md](../../stack_debug.md) 的流程：先用 `maps.txt` 判断地址属于哪个模块，算出模块内偏移后再 `addr2line`；不要拿 `si_addr` 直接解析。
