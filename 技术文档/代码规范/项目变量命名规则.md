# 项目变量命名规则整理

整理日期：2026-10-15。本文根据项目现有源码归纳命名习惯，用于本次 TS3116K0 功能码修改及后续同模块开发；不是项目原有的统一强制规范。

## 1. 总体规则

项目业务 C/C++ 代码主要采用“作用域前缀（可选）+ 类型或用途前缀 + 业务含义”的形式，业务含义通常使用首字母大写的单词组合。例如 `s_bSystemUpdateState`、`iCheckResult`、`nBufSize`、`acOldSoftVer`、`pNewVerFile`。

不同模块存在混用：整数有 `i` 和 `n`，字符串有 `ac`、`sz` 和 `str`，结构体有 `st` 和 `t`，部分新模块使用没有类型前缀的名称。因此新增变量优先与所在函数、文件保持一致，不能仅凭前缀推断实际 C/C++ 类型或作用域。

## 2. C/C++ 类型与用途前缀

| 前缀 | 常见含义 | 项目已有示例 | 新增变量选择原则 |
| --- | --- | --- | --- |
| `i` / `n` | 整数、返回值、数量、索引 | `iRet`、`iCheckResult`、`nBufSize`、`nIndex` | SYS 升级函数多用 `i`；MPU 功能码处理多用 `n`，跟随局部习惯 |
| `b` | 布尔语义或开关，实际类型也可能为 `int` | `bCheckMd5`、`bDeleteFile`、`bUpdating` | 用于是否启用、是否存在等判断 |
| `ui` | `unsigned int` | `uiVersion` | 跟随实际声明，不用来表示普通有符号整数 |
| `ul` / `ull` | `unsigned long` / `unsigned long long` | `ulFileLen`、`s_ullOperationBit` | 跟随实际声明 |
| `e` | `enum`（枚举）类型或取值来自枚举的变量，来自 enumeration | `eType`（`IPC_PARA_TYPE_ENUM`）、`eOSDTitlePosition`（`IPC_OSD_POSITION_ENUM`）、`eParaType` | 变量本身为枚举类型时使用；`ipchead.cpp` 的 `IPCHEAD_SetIpcPara()` 等对外接口将 `eParaType` 声明为 `unsigned long`，函数内再转换为 `IPC_PARA_TYPE_ENUM eType`，此时 `e` 只表示取值语义为枚举，跟随该接口已有声明 |
| `ac` | 字符数组或字符串缓冲区 | `acOldSoftVer`、`acPackPath`、`acCmd` | SYS 升级流程新增字符数组使用 `ac` |
| `sz` / `str` | 字符串 | `szVersion`、`szDeviceType`、`strDevSn` | 现有替代写法，跟随所在模块 |
| `auc` | `unsigned char` 数组 | `aucEncInfo`、`aucDetectionArea` | 表示字节数组，区别于字符串缓冲区 |
| `p` | 指针 | `pCfg`、`pNewVerFile`、`pGetFuncInfo` | 名称应包含所指对象的含义 |
| `psz` | 字符串指针，包括 `const char *` 参数 | `pszDeviceType`、`pszSerialNum` | 字符串参数可使用 `psz`，输出缓冲区也需结合函数签名判断 |
| `st` / `t` | 结构体或复合对象 | `stNewVer`、`stSystemInfo`、`s_tDevCap_pub` | 跟随模块已有写法 |

数组前缀可组合类型前缀，例如项目已有 `auc` 和 `aull`。本次 `unsigned long[4]` 据此命名为 `aulVersionValues`；`aul` 是按已有组合方式推导，并非该升级文件原有的统一约定。

## 3. 作用域与常量

| 形式 | 项目中的常见用途 | 项目已有示例 |
| --- | --- | --- |
| `s_` | 文件内静态状态或缓存 | `s_bSystemUpdateState`、`s_szModelType` |
| `sg_` | 某些模块的静态全局状态 | `sg_bUpdateStart`、`sg_tFileMutex` |
| `g_` | 全局共享数据 | `g_UpgradeFileVer`、`g_iMotionDetectionSettingChannel` |
| `m_` | C++ 成员或部分结构体字段 | `m_src`、`m_des`、`m_nCount`、`m_iChannelNum` |
| 全大写加下划线 | 宏、常量、枚举项 | `MAX_DEVICE_VERSION_LEN`、`FUNC_TYPE_MODELCHANGE` |

作用域以实际声明为准。例如 `s_` 与 `static` 通常配合使用，但历史代码中并非所有成员或静态变量都有统一前缀。已有 SDK 接口、结构体字段、枚举值和配置键的名称应按原定义使用。

## 4. Python 与 Shell

Python 局部变量和函数沿用 `snake_case`，常量使用全大写加下划线。例如 `build_model_package.py` 中的 `current`、`replaced`、`get_group_names()`、`MAX_GROUPS`。本次测试脚本的 Python 变量继续使用 `old_non_ascii`、`new_non_ascii` 一类小写加下划线的形式；生成的 C++ 代码采用上述业务 C/C++ 前缀。

Shell 脚本混用小写变量和大写环境/保存变量，例如 `Changeversion.sh` 的 `arr`、`base`、`file`、`OLD_IFS`、`IFS`。新增变量跟随所在脚本，避免重新定义环境变量和系统已有变量。

## 5. 本次新增变量调整

| 位置 | 原名称 | 调整后 | 理由 |
| --- | --- | --- | --- |
| `MpuPubSupportsDerivedModelChange()` | `pCfg` | `pVersionCfg` | 指针前缀已符合习惯，补充版本配置对象的业务含义 |
| 同上 | `major` | `nMajorVersion` | MPU 局部整数使用 `n` 前缀 |
| 同上 | `minor` | `nMinorVersion` | MPU 局部整数使用 `n` 前缀 |
| 同上 | `revision` | `nReversion` | 使用 `n` 前缀，并与已有 `Reversion` 配置键术语一致 |
| `CompareUpdateVersion()` | `left` | `pszLeftVersion` | 字符串指针参数，明确比较对象 |
| 同上 | `right` | `pszRightVersion` | 字符串指针参数，明确比较对象 |
| 同上 | `numeric` | `bNumericCompare` | `int` 承载布尔语义，使用 `b` 前缀 |
| `check_version()` | `upgrade_model` | `acUpgradeModel` | 跟随 SYS 函数的字符数组命名 |
| 同上 | `versionValues` | `aulVersionValues` | 四段无符号长整数数组 |
| 同上 | `bDerivedModelChange` | `iDerivedModelChange` | 按用户要求使用 `i` 前缀，实际类型为 `int`，继续表示型号变更状态 |

`FUNC_TYPE_EUROPE_MODELCHANGE`、`DERIVED_MODELCHANGE_MIN_VERSION` 已符合枚举项和宏的全大写命名。`uc2syscontrol.cpp` 的本次修改未新增变量。已有 `raw_model`、`display_model`、`func_codes` 和版本解析函数参数属于修改前源码，新增分支继续引用其原名称。

测试脚本中生成的 C++ 配置替身、授权数组、版本缓冲区及局部变量也按相同规则调整；Python 变量采用 Python 自身的命名习惯。
